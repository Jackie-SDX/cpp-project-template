CPP PROJECT TEMPLATE — OPEN BUGS / CI COACHING NOTES

Date: 2026-09-16
Release target: v0.0.9

These items are deliberately documented for follow-up. They are not release blockers for the currently validated release path.

1. Windows MinGW CI — toolchain/CI integration
   - MinGW x64 and i686 jobs have repeatedly spent excessive time inside the vcpkg stage even when the GitHub Actions cache step reports success.
   - GitHub Actions cache restoration and vcpkg binary-cache reuse are separate mechanisms; a restored archive does not guarantee vcpkg ABI compatibility or package reuse.
   - The CI required explicit MSYS2 MinGW toolchain setup and PATH selection rather than depending on whatever gcc/g++ happened to be visible on the Windows runner.
   - The MinGW jobs should be investigated later for deterministic toolchain provisioning, ABI-stable cache namespaces, and whether the desired vcpkg packages are actually restored versus rebuilt.

2. Windows LLVM CI — toolchain/vcpkg integration
   - LLVM jobs also spend disproportionate time in vcpkg despite a successful GitHub Actions cache-restore step.
   - The LLVM overlay triplet uses clang-cl semantics and must remain aligned with the Visual Studio/Windows host environment used by vcpkg.
   - The CI should be investigated later for deterministic LLVM toolchain discovery, exact ABI compatibility, and package-level binary-cache reuse.

3. Cache observability
   - Future work should distinguish three states in logs: GitHub Actions archive hit, vcpkg binary-cache package hit, and source rebuild.
   - A successful Actions cache step must not be treated as proof that vcpkg skipped compilation.

4. Release validation note
   - ARM64 Windows package smoke remains a separately documented known bug and is intentionally left unchanged.

Follow-up: create dedicated GitHub issues for the MinGW and LLVM investigations and address them after the v0.0.9 release.
